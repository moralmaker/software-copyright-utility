# software-copyright-utility

从真实项目源码，引导生成中国大陆 **计算机软件著作权登记** 所需材料。

这不是一个网页，也不是“一键出件、不问你确认”的脚本。它是给 Cursor / Claude 用的 **Agent Skill**：你在对话里说“帮我生成软著申请资料”，AI 会分析当前项目、先写出可审阅的 Markdown 草稿，**每一步停下来等你确认**，最后再生成正式 Word / TXT。

当前版本：`1.7`

---

## 它能帮你做什么

对照常见软著提交材料，本项目会产出：


| 材料          | 说明                                    |
| ----------- | ------------------------------------- |
| 登记申请表 Word  | 按官方《计算机软件著作权登记申请表》结构填写                |
| 申请表信息 TXT   | 方便你对照官网表单逐项粘贴或核对                      |
| 程序鉴别材料 Word | 真实源码分页；满 60 页时交前 30 页 + 后 30 页，不足则交全部 |
| 操作手册 Word   | 按官方《软件操作说明书样本》结构写用户说明书，不是研发文档         |
| 生成报告        | 记录本次用了哪些字段、代码来源、截图情况和校验结果             |


核心原则：

- **代码必须来自你的项目**，禁止 AI 编造源码。
- **先草稿、后正式文件**。未确认前不会生成正式 Word / TXT。
- **行业、功能、手册章节由模型读项目后判断**，不靠关键字模板瞎套。
- 正式 Word 用黑色正文；软件全称、版本号以你确认过的申请表字段为准。

## 适合什么项目

优先支持能看出页面和业务的项目，尤其是前端 / 全栈：

- Vue、React、Next.js、Nuxt、UniApp、Taro、小程序
- 带页面、路由、组件、接口封装的 Web / 桌面套壳应用
- 前端不够 60 页时，会再补充 Python、Java、Go、C# 等后端源码

不太适合：几乎没有源码的空仓库、纯配置仓库、只有二进制或编译产物的目录。

## 新手 3 步上手



### 1. 准备环境

必装：

```bash
python3 --version          # 需要 3.10 或更高
python3 -m pip install python-docx
```

选装（Word 格式更规范，建议装）：

- [.NET SDK 8.0+](https://dotnet.microsoft.com/download)
- 装完后执行 skill 内的环境脚本：

```bash
bash software-copyright-utility/vendor/docx-toolkit/scripts/setup.sh
```

不装 .NET 也能继续：会用基础 DOCX 兜底生成 Word，流程开始时 AI 会问你选哪一种。

### 2. 安装这个 Skill

把带 `SKILL.md` 的目录放到 Cursor 能读到的技能目录，例如：

```text
~/.cursor/skills/software-copyright-utility/
├── SKILL.md
├── scripts/
├── references/
├── assets/
└── vendor/
```

本仓库里，真正的技能包是内层的 `software-copyright-utility/` 文件夹（里面有 `SKILL.md`），不是仓库根目录。

### 3. 打开你的项目，对 AI 说一句话

在 **待申请软著的项目** 工作区里打开 Cursor，发送：

```text
帮我生成软著申请资料
```

也可以说：`软著申请`、`生成软著代码材料和操作手册`、`填软著申请表`。

然后按对话提示回复即可。所有材料会写到当前项目下的 `软件著作权申请资料/`，不会写到系统临时目录。

## 使用流程（跟着对话走）

整条流程是 **分析 → 草稿 → 你确认 → 正式文件**。AI 在每个门禁都会停住，等你回复后再继续。不要期望它一口气跑完。

```text
检查环境
   ↓ 你选择：装完整 Word 环境，或用基础 Word 继续
定位项目
   ↓ 多个项目时你指定目录
分析项目（框架、页面、源码行数等）
   ↓
形成业务理解
   ↓ 你确认行业、用户、核心功能
确认申请表字段
   ↓ 你补全著作权人、日期、硬件环境等
确认要抽取的代码文件
   ↓ 你勾选或改选
生成 Markdown 草稿（代码 / 申请表 / 操作手册）
   ↓
选择截图方式（可跳过）
   ↓
你确认全部草稿
   ↓
生成正式 Word / TXT
   ↓
三轮校验（文件是否齐全、代码能否回溯、名称版本是否一致）
```



### 第 1 步：环境检查

AI 会创建 `软件著作权申请资料/`，并告诉你：

- Markdown 草稿、TXT、基础 Word 是否可用
- 完整 OpenXML Word 环境是否可用

完整环境缺失时必须先选一项：

1. 安装完整 DOCX 环境（更规范）
2. 使用基础 DOCX 继续



### 第 2 步：定位并分析项目

通常把待申请项目放在当前文件夹。AI 会避开 `node_modules`、构建产物和本 skill 自己的目录，找出项目根目录。

有多个候选时必须由你指定。分析内容包括：

- `package.json`、README、依赖、启动命令
- 前端框架和主要语言
- 入口、路由、页面、组件、接口、状态管理
- 源文件数量和源程序行数
- 软件名称、功能、运行命令的建议值



### 第 3 步：确认业务理解

在写申请表和操作手册之前，会先生成 `草稿/业务理解.md`。请重点核对：

- 软件是干什么的
- 属于什么行业
- 给谁用
- 核心功能和典型操作流程
- 申请表建议口径

写得不对就直接改，或回复修改意见。**这一步没确认，不会进入申请表和手册。**

### 第 4 步：补全申请表字段

项目能推断的字段会先给出建议值；著作权人、日期、硬件 / 系统环境必须由你确认或手填。

常见必填项：

- 软件全称、版本号（项目若是 `V0.x`，一般会问你是否改成软著常用的 `V1.0`）
- 开发完成日期（`YYYY-MM-DD`）
- 著作权人（自然人 / 法人、姓名、证件号等）
- 开发 / 运行的硬件环境和操作系统
- 开发工具（格式：`开发环境: Windows 11/开发工具: Visual Studio Code`，不要把 React、Vue 写进这个字段）
- 主要功能（500～1300 字）

软件全称一旦确认，正式文件名、代码页眉、操作手册封面都会用这个名字。

### 第 5 步：确认代码抽取范围

会先给你两份文件：

- `草稿/代码文件候选清单.md`：候选说明
- `草稿/代码文件选择.json`：可编辑的选择结果

默认优先抽前端：入口、路由、页面、核心组件、接口封装、状态管理、工具函数。不够 60 页再补相关后端。

你要做的：看清单，确认或改 `selected`。不要默认交整个仓库。代码按 **完整文件** 抽取（去掉纯空行），不支持只截某个文件中间几行。

### 第 6 步：生成并审阅草稿

确认代码范围后，会生成：

- 代码草稿：满 60 页为 `代码-前30页.md` + `代码-后30页.md`；不足且已无源码可补则为 `代码-全部.md`
- `申请表信息.md`
- `操作手册.md`（封面 → 目录 → `1 引言` → `2 软件概述` → `3 系统使用`）
- `操作手册自检记录.md`（内部扩写和去套话记录）

操作手册按普通用户视角写：这个页面干什么、从哪进、点什么、填什么、操作后看到什么。不会写成接口说明或框架介绍。

### 第 7 步：选择截图（可跳过）

手册写完后，必须先选一种截图方式：


| 选项                  | 适合                                      |
| ------------------- | --------------------------------------- |
| Chrome DevTools MCP | Web / 浏览器项目                             |
| 微信开发者工具 MCP         | uni-app / Taro 等编译到微信小程序的项目（小程序优先选这个）   |
| Codex Computer Use  | 需要在桌面或浏览器里点几下再截的场景                      |
| 自己截图                | 把 PNG / JPG / WebP 放到 `软件著作权申请资料/用户截图/` |
| 先不截图                | 回复“先跳过截图”；手册里仍会留下可见的截图预留文字              |


需要登录的页面：先给你账号让 AI 登录，或你自己登录后再说“已登录”。**不会用登录页顶替功能页截图。** 账号密码只用于当场登录，不会写入任何申请资料。

### 第 8 步：确认草稿，生成正式文件

打开 `软件著作权申请资料/草稿/`，重点检查：

- 软件名称、版本号全文一致
- 申请表里不再有“待用户确认”
- 代码确实来自你勾选的源文件
- 操作手册像说明书，每个核心页面有操作说明和截图位

回复“草稿确认，可以生成正式资料”后，才会写入 `正式资料/`。

## 生成后你能拿到什么

```text
<你的项目>/软件著作权申请资料/
├── 环境检查.md
├── 草稿/
│   ├── 业务理解.md
│   ├── 申请表信息.md
│   ├── 操作手册.md
│   ├── 代码-前30页.md          # 或 代码-全部.md
│   ├── 代码-后30页.md
│   ├── 代码文件选择.json
│   └── 代码提取清单.md
├── 截图/                       # 自动截图或整理后的图片
├── 用户截图/                   # 你自己放入的原图
└── 正式资料/
    ├── 申请表信息.txt
    ├── 计算机软件著作权登记申请表.docx
    ├── <软件全称>-代码(前30页).docx
    ├── <软件全称>-代码(后30页).docx
    ├── <软件全称>_操作手册.docx
    └── 生成报告.md
```

代码不足 60 页时，正式代码文件名是 `<软件全称>-代码(全部).docx`。

拿到文件后：用 Word 打开核对页眉、页数和截图，再登录中国版权保护中心网站填报。本工具只准备材料，不代替网上申报。

## 对话时你会被问到什么

下面这些阶段 **必须等人回复**，即使开了自动继续也不会跳过：


| 阶段    | 你需要做的事                  |
| ----- | ----------------------- |
| 环境    | 选完整 Word 环境，或基础 Word 继续 |
| 项目    | 多个目录时指定项目根目录            |
| 业务理解  | 确认行业、用户、功能和申请口径         |
| 申请表字段 | 补全著作权人、日期、硬件 / 系统环境     |
| 代码选择  | 确认或修改要抽取的源文件            |
| 截图方式  | 选一种截图方式，或明确说跳过          |
| 草稿总确认 | 确认可以生成正式 Word / TXT     |


建议一次把能确定的信息说清楚，减少来回，例如：

```text
帮我生成软著申请资料。
软件全称：某某管理系统
版本号：V1.0
著作权人：张三（自然人）
开发完成日期：2026-03-01
未发表。
开发环境：macOS 15 / Visual Studio Code
先跳过截图。
```

## 常见问题

**必须会写代码、会跑脚本吗？**  
不用。主路径就是跟 AI 对话。脚本是给 Agent 用的，你只要确认内容和字段。

**会不会把仓库里的密钥、身份证写进代码材料？**  
代码来自你确认过的源文件。申请表里的证件号是你自己填的登记信息。抽取前请先检查候选清单，不要把含密钥、`.env`、私钥的文件勾进去。

**代码不够 60 页怎么办？**  
先从相关源码继续补选。候选用尽仍不足 60 页，就生成“全部代码”一份，这符合登记习惯。

**操作手册看起来像 AI 套话怎么办？**  
在业务理解或手册草稿阶段直接指出哪一页写空了。流程要求按真实页面写用途、入口、控件和结果，并做多轮自检；仍不对就让它按你的修改重写该章。

**小程序怎么截图？**  
优先用微信开发者工具 MCP：先编译出 `dist/**/mp-weixin`，在开发者工具里导入该目录，再按页面截图。

**正式 Word 的软件名和我想的不一样？**  
以 `草稿/申请表信息.md` 里已确认的“软件全称”“版本号”为准。先改申请表再重新生成正式资料。

**输出跑到别的目录了？**  
正常情况只写当前工作目录下的 `软件著作权申请资料/`。请在待申请项目的根目录发起对话，不要在无关仓库里跑。

## 仓库目录

```text
software-copyright-utility/          # 本仓库
├── README.md
└── software-copyright-utility/      # 可安装的 Skill 包
    ├── SKILL.md                     # Agent 工作流（先读这个）
    ├── agents/openai.yaml
    ├── assets/                      # 官方申请表 Word 模板
    ├── references/                  # 字段、手册、代码抽取规则
    ├── scripts/                     # 分析、抽取、生成 Word
    └── vendor/docx-toolkit/         # 内置 Word 生成与校验
```

脚本只负责收集证据、校验字段和出文件；行业判断、功能抽取、手册结构由模型读项目后决定。


| 脚本                             | 作用                   |
| ------------------------------ | -------------------- |
| `check_environment.py`         | 检查 Python / Word 环境  |
| `analyze_project.py`           | 分析项目结构与源码规模          |
| `generate_business_context.py` | 收集业务证据，写入业务理解        |
| `generate_application_info.py` | 生成申请表草稿              |
| `propose_code_selection.py`    | 列出代码候选，不自动全选         |
| `extract_code_material.py`     | 按已确认清单抽取真实源码         |
| `generate_manual_draft.py`     | 生成操作手册草稿和自检记录        |
| `capture_screenshots.py`       | 整理用户提供的截图            |
| `confirm_stage.py`             | 记录各阶段人工确认            |
| `build_docx_from_md.py`        | 草稿确认后生成正式 Word / TXT |
| `build_application_form.py`    | 按官方模板填写申请表           |


日常使用不需要手动调用这些命令。

## 注意事项

- 材料必须反映软件真实功能。没有的页面、接口、行业能力不要写进去。
- 著作权人、证件号、发表日期等法律信息由你核对，AI 不能替你承担登记责任。
- 本工具协助准备鉴别材料和申请表文案，不保证审查通过，也不代替中国版权保护中心的网上申报。
- 生成目录已被 `.gitignore` 忽略，避免把申请资料和证件信息误提交到 Git。
